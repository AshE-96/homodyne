The instrument is not broken and the number is not fake. It answers a different question than the one being asked — and no amount of extra precision will fix that.

A benchmark can be accurate, repeatable and technically flawless while measuring the wrong construct. When that happens the score isn’t wrong — our reading of it is.

Most benchmark projects start at stage two — collect questions, build a dataset, run it. A dataset assembled before the target exists can measure the wrong task very precisely.

For this chapter’s project the intended use is narrow on purpose: not “which model is smartest”, but which tool should a non-technical founder put into a working pilot for first-pass market research.

The metric sees a proxy, not the whole construct

Two ways the construct breaks

Underrepresentation Only a small part of the concept made it into the test. Counting links and calling the result “research quality” is the classic version.
Irrelevant variance Something outside the concept moves the score anyway — a better interface, a faster operator, or simply a longer answer scoring higher on a loose rubric.

The fix is not to claim full coverage. It is to say precisely which evidence you have and which part of the concept stayed outside the circle.

A task needs an operator, an output and a unit

CaseOne brief, run once, under a fixed time and cost budget the primary unit
ReportWhat the tool produced for that case 1 per case
ClaimA single factual assertion inside the report many per report
Claim–source pairThe unit citation support is actually measured on many per claim
Action itemThe unit actionability is measured on a handful per report

Two thousand claims spread across forty-eight reports are not two thousand independent observations. Claims inside one report share a prompt, a context and a set of sources. Treat them as independent and you manufacture confidence you never measured.

A narrower claim can be a stronger one

Inside the claim

  • English-language output
  • Public web data only
  • First-pass market research
  • B2B and B2C use cases
  • Named tool versions, in a fixed window
  • ≤ 30 minutes and ≤ $10 per case

Deliberately outside

  • Persian-language output
  • Private or paid databases
  • Legal or financial due diligence
  • Expert market-intelligence workflows
  • Free tiers of the same tools
  • Any claim about the underlying base model

Claim boundary v0.1 Useful for choosing a tool to pilot for first-pass market research, under this dataset and protocol. Weak when the market is thin or non-English. Does not prove that one tool is best for all research, all languages or all users.

“The traditional method” is not a baseline.

Who ran it, with what experience, using which tools, for how many minutes, against which template — all of it has to be written down, or the comparison has no meaning. Compare only AI tools with each other and they might all be losing to this.

Where we started “What’s the best AI tool for market research?”

1 · Decision

Pick at most two tools for a non-technical founder to pilot.

2 · Construct

Evidence quality and decision usefulness, under time and cost limits.

3 · Task

Produce an English market-research report from a standard brief, public web data only.

4 · Unit

Case, with report, claim, citation, action item and run nested inside it.

5 · Scope

Named tools and versions, fixed window, ≤ 30 minutes and ≤ $10 per case.

6 · Baseline

A manual search-and-spreadsheet workflow with a fixed template.

7 · Claim boundary

Valid only for the tools, dataset, protocol, versions and window recorded.
