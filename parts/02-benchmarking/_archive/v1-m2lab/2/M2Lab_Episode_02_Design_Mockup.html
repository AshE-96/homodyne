No corner is better than another. Fixed environments are cheaper and repeatable but drift from the real job; live ones are realistic but pull the tool version, the network and the UI into the experiment. The map doesn’t remove the complexity — it shows you where it sits.

Give the same base model a better browser tool, more memory or a different scaffold and the score moves. So the claim has to be about the system under this configuration — not about the model’s name.

A citation can exist and still support nothing

Claim in the report The market grew by roughly a third last year, driven mostly by mid-size buyers.
↳ cited: industry-overview-2024.pdf, page 12

Gate 1

Exists

The link resolves and the page is real.

Gate 2

Relevant

The page is genuinely about this market.

Gate 3

Supports

It reports total revenue — it never breaks growth down by buyer size.

Counting links scores this claim as sourced. Citation support has to be measured at the claim level, or a benchmark rewards the appearance of evidence.

Refusing more is not the same as being safer

Attack successHarmful requests that get through
Safer ←→ Worse
Over-refusalLegitimate requests turned away
Useful ←→ Useless

Tighten the refusal policy → one bar falls, the other climbs

A model that refuses everything scores perfectly on one axis and destroys the product on the other. Safety needs both numbers reported together — and fairness needs the same treatment, because an average hides the group it fails.

Pause here — three seconds

Same pattern all three times: start from the decision, name the failure that would cost you, then choose the families. A famous benchmark was never the starting point.

How to pick a family without starting from a name

Decision what are you actually choosing?
→
Costly failure what would hurt if it went wrong?
→
Required evidence what would you need to see?
→
Benchmark family only now does a name appear

Build the evidence stack around the decision

Retrieval Were relevant and varied sources actually found?
Factuality Is each claim supported by the source it cites?
Product outcome Does the output make the founder’s next decision clearer?
Efficiency What does one successful report cost in time and money?
Robustness Does quality collapse on another industry, language or thin market?
Deliberately not centralGeneral knowledge — the decision is choosing a research tool, not ranking intelligence.
Deliberately scopedAgent behaviour — measured only within web use, not as a general capability.

Narrowing the stack is not a weakness. It is the condition for a claim you can defend.
