**وضعیت:** قاب ۱ تا ۹ و ۱۳ تا ۱۵ آمادهٔ تمرین؛ عددهای قاب ۸ و ۹ از اجرای واقعی محلی ۲۴ نوامبر ۲۰۲۶‌اند (بدون هیچ مدل زبانی؛ خرابکاری عمدی و برنامهٔ دمو). قاب ۱۰، ۱۱ و بخش [RUN] قاب ۱۲ منتظر اجرای API‌اند (NOT RUN YET). منبع‌ها ۲۳ نوامبر ۲۰۲۶ روی وب بازبینی شدند.
**قالب:** AI in Production · ایدهٔ ۱۲ فایل «۲۳ آزمایش» · **انتشار:** پنجشنبه ۲۰۲۷-۰۴-۰۸ (۱۹ فروردین ۱۴۰۶)، 18:00 تهران · **زمان برآوردی:** حدود ۱۳:۵۱ · **واژهٔ گفتاری:** 1834 (همهٔ شاخه‌ها، شمارش check-season-01؛ ضبط با یک شاخه حدود 1762) · **قاب:** ۱۵
**هوک:** Shock — «این فرم از نظر کامپیوتر بی‌نقصه… و مبلغش ده برابر غلطه.» (مثال دست‌ساز، برچسب‌خورده)

**جملهٔ مرکزی:** فرم مرتب فقط یعنی «خوانده می‌شود و در قالب جا می‌شود»؛ درستی عدد را باید جدا سنجید، با قانون‌های کسب‌وکار، و جایی که قانون نمی‌رسد با تکرار برای مشتری یا تأیید آدم.

**مرز ادعا:** قالب (schema) نوع و بعضی قیدها را چک می‌کند؛ معتبر بودن نحوی، درستی در دنیای واقعی را نتیجه نمی‌دهد. داده‌ها ساختگی‌اند (۱۰۰ پیام آزمون قفل‌شده + ۲۸ پیام dev، از روی الگو)؛ نتیجهٔ مدل‌ها مال یک مدل، یک دستور و یک تاریخ است؛ قانون قیمت فقط چون فهرست قیمت داریم کار می‌کند.

**زنجیره:** از HMD-019 («بیرون آزمایشگاه، کسی جواب‌نامه نداره. فرم بی‌نقصه، ولی اگه یه عدد داخلش غلط باشه چی؟») ← قاب ۱ و ۲ همین را برمی‌دارند و جواب کوتاهش را می‌دهند (فرم مرتب فقط چراغ «ساختار» را روشن می‌کند) ← تیزر HMD-021: «امروز هر خونهٔ فرم یه قانونِ نوشته‌شده داشت… تنها چیزی که فرق داره اسم متقاضیه. اگه امتیاز جابه‌جا بشه، هیچ قالبی اینو نمی‌گیره. قسمت بعد: دو رزومهٔ یکسان، دو اسم.» (شرطی؛ هیچ نتیجه‌ای از HMD-019 یا HMD-021 ادعا نمی‌شود.)

**تصمیم مدیر محصول:** کدام سفارش خودکار ثبت شود، کدام یک بار اصلاح شود، و کدام پیش آدم برود؛ با قانون‌ها و سقف قبولی (حداکثر ۲ از ۱۰۰ خودکار و غلط) که پیش از اجرا قفل شده‌اند، و «تکرار برای مشتری» برای خطاهایی که هیچ چراغی نمی‌بیند.

## اجرای API (طراحی شده، اجرا نشده)

```bash
env -u GEMINI_API_KEY -u ANTHROPIC_API_KEY -u OPENAI_API_KEY HOMODYNE_MODEL=mock:echo \
  python3 parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py --selftest
python3 tools/llm.py check
python3 parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py plan
python3 parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py run --limit 3
python3 parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py run          # y/N پیش از خرج؛ --yes بدون پرسش
python3 parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py report
```

`run` ۳۰۰ فراخوانی دارد (۳ روش × ۱۰۰ پیام) و حداکثر ۱۰۰ فراخوانی اصلاح؛ `plan` حدود ۰٫۵۲ میلیون توکن ورودی و، با فرض ۸۰۰ توکن خروجی (با استدلال)، ۰٫۳۲ میلیون توکن خروجی برآورد می‌کند. `run` پیش از خرج y/N می‌پرسد (`--yes` بدون پرسش). تا وقتی `prices.json` خالی است، `plan` و `run` سقف بدبینانه‌ای با قیمت جایگزینِ تاریخ‌دار (نه قیمت رسمی) و ۸۰۰۰ توکن خروجی برای هر فراخوانی نشان می‌دهند: حدود ۲۴۸ دلار برای Claude. `run` و `report` اگر `data/test.jsonl` با `FROZEN.json` نخواند متوقف می‌شوند. روش «قالب اجباری» از پارامتر اختیاری `schema=` در `tools/llm.py` استفاده می‌کند. `report` جدول کامل با مخرج‌ها، بازهٔ Wilson، تفاوت جفتی (bootstrap و McNemar دقیق) و جمله‌های گفتاری قاب ۱۰ تا ۱۲ را با عدد واقعی و به حروف چاپ می‌کند و شاخه را خودش انتخاب می‌کند.

## ریسک‌های باز

- **نتیجهٔ مدل‌ها هنوز نیامده.** اگر هر سه روش تقریباً بی‌خطا باشند، داستان به «قانون‌ها و تکرار برای مشتری» تکیه می‌کند؛ اگر قالب اجباری درستی را پایین بیاورد (R05)، همان شاخه گفته می‌شود. متن برای هر دو آماده است.
- **پیام‌های الگویی از پیام واقعی تمیزترند** و هر پیام یک دام اصلی دارد؛ مدل‌های قوی ممکن است روی آن‌ها بهتر از واقعیت باشند. در متن و مرز ادعا گفته شده.
- **۱۰۰ پیام کوچک است**؛ بازهٔ Wilson حدود ±۱۰ واحد درصد. تفاوت روش‌ها ممکن است معنادار نشود (شاخهٔ ب قاب ۱۰).
- **«تومن» محاوره‌ای وابسته به بافت است** (در حقوق گاهی یعنی میلیون)؛ در داده، مبلغ هر پیام «تومن بی‌هزار» با قیمت کالا معنایش را قطعی می‌کند.
- **حذف چهار صفر:** قانون تصویب شده (R06)؛ نام واحد تازه در گزارش‌ها متناقض است؛ متن آن را نام نمی‌برد.
- **قانون ۵ روی آزمون تنظیم شد.** پس از دیدن نتیجهٔ برنامهٔ دمو (نه مدل) روی همان ۱۰۰ پیام آزمون اضافه شد؛ هیچ خروجی مدلی هنوز وجود نداشت. متن، `protocol.md`، `data/FROZEN.json` و README این را صریح می‌گویند؛ dev هم همان سوراخ را نشان می‌داد (۳/۲۸ ← ۰/۲۸). عددِ «۲ از ۱۰۰» دمو بنابراین خوش‌بینانه است؛ عدد مدل‌ها روی قانونی سنجیده می‌شود که پیش از دیدنشان قفل شد.
- **تفاوت ارائه‌دهنده‌ها در قالب اجباری:** Anthropic قیدهای عددی را نمی‌پذیرد؛ قالب ما هیچ‌کدام را ندارد، پس سه سرویس یک قالب یکسان می‌گیرند. صفحه‌های ai.google.dev برای ابزار بازبینی ما ۴۰۳ دادند؛ نام فیلد Gemini از کد رسمی SDK تأیید شد (R03c). پیش از اجرا با `run --limit 3` روی Gemini امتحان شود.
- **اصلاحِ خطای قیمت خوش‌بینانه است:** پیام اصلاح فقط نام قانون را می‌گوید، نه جمع کل؛ ولی فهرست قیمت در دستور هر سه روش هست، پس مدل می‌تواند جمع را حساب کند.
- **`make selftest`** تست HMD-020 را اجرا نمی‌کند (Makefile بیرون پوشهٔ من است)؛ برای افزودنش یک خط کافی است: `HOMODYNE_MODEL=mock:echo $(PY) parts/05-season-02/hmd-020-valid-json-wrong-answer/artifact/testbench.py --selftest > /dev/null`.
- **SDK نصب‌شدهٔ anthropic (0.45.2) قدیمی است** و `output_config` و `fallbacks` را نمی‌شناسد؛ پیش از اجرای Claude: `pip install -U anthropic`.
- **هزینهٔ استدلال:** `max_tokens` ۸۰۰۰ است تا پاسخ مدل استدلالی بریده نشود؛ برآورد خروجی `plan` فرض است، با `--limit 3` اندازه بگیر.
