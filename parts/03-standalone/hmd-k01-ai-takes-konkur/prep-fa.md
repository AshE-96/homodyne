## ۱. چهار کلید (یک بار)

۱. کلیدها را بساز و برای هر حساب **سقف خرج ماهانه** بگذار (پیشنهاد: پیش از پیش‌آزمون کم، بعد بر اساس `plan` بالا ببر). کد ما سقف دلار سخت ندارد؛ فقط پیش از `run` برآورد بالا را نشان می‌دهد و `[y/N]` می‌پرسد. پس سقف واقعی همان سقف حساب‌هاست. در Google، بودجهٔ Cloud Billing به‌طور پیش‌فرض فقط هشدار می‌دهد و جلوی خرج را نمی‌گیرد [VERIFY روز اجرا در صفحهٔ Billing]؛ برای Gemini اعتبار کم یا سقف پروژه بگذار:

| کلید | از کجا | برای |
|---|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com ← API Keys | Claude |
| `GEMINI_API_KEY` | aistudio.google.com ← Get API key | Gemini |
| `OPENAI_API_KEY` | platform.openai.com ← API keys | GPT |
| `OPENROUTER_API_KEY` | openrouter.ai ← Keys (اعتبار پیش‌پرداخت؛ سقف کلید را هم بگذار) | دو مدل باز |

۲. هر چهار خط را در فایل `private/keys.env` بگذار (git آن را نمی‌بیند؛ کلید وارد محیط هیچ پردازه‌ای نمی‌شود):

```text
ANTHROPIC_API_KEY=...
GEMINI_API_KEY=...
OPENAI_API_KEY=...
OPENROUTER_API_KEY=...
```

۳. کتابخانهٔ Claude و یک بررسی کوچک (هر کدام یک درخواست خیلی کوچک، چند سِنت هم نمی‌شود):

```bash
pip install -U anthropic
brew install poppler          # pdftoppm و pdftotext برای konkur_prep.py render/text/crop
python3 tools/llm.py check
```

`check` بی‌تنظیم، Claude را امتحان می‌کند. برای بقیه، شناسهٔ مدلی را که می‌خواهی بده (شناسه‌ها را با Claude در قدم ۳ انتخاب می‌کنیم؛ این‌جا فقط کلید آزموده می‌شود):

```bash
HOMODYNE_MODEL=gemini:<id> python3 tools/llm.py check
HOMODYNE_MODEL=openai:<id> python3 tools/llm.py check
HOMODYNE_MODEL=openrouter:<vendor/id> python3 tools/llm.py check
```

هر کدام باید یک خط JSON با `"text": "ready"` (یا شبیهش) چاپ کند. خطای `HTTP 401` یعنی کلید غلط است؛ `HTTP 402` در OpenRouter یعنی اعتبار نداری.

### Claude بعدش چه می‌کند (تو فقط بازبینی می‌کنی)

۱. `konkur_prep.py render` و `text` (صفحه‌ها با ۱۵۰ dpi و لایهٔ متن اگر باشد).
۲. `template` برای هر آزمون با بازهٔ شمارهٔ هر درس.
۳. **رونویسی دو مرحله‌ای:** نسخهٔ A از تصویر صفحه‌ها؛ نسخهٔ B در یک گفت‌وگوی تازه از رندر ۲۰۰ dpi، بی‌آنکه A را ببیند؛ `diff A B`؛ هر اختلاف با تصویر صفحه حل و در `notes` نوشته می‌شود. فرمول‌ها LaTeX، شکل‌ها با جعبهٔ برش و `crop`.
۴. کلید دو بار جداگانه تایپ و diff می‌شود؛ `keys` آن را روی فایل می‌نشاند؛ `validate` باید `ok` بدهد.
۵. `konkur_prep.py sample --n 25` فهرست ۲۵ سؤال تصادفی می‌دهد. **کار تو:** هر کدام را با دفترچه مقایسه کن (متن، چهار گزینه، شکل، کلید). یک خطا ← کل آن درس دوباره بازبینی می‌شود. بعد در `exam.checked_by_owner` تاریخ را بنویس.

## ۴. تمرین MOCK (رایگان، بی‌کلید)

```bash
python3 $A/konkur_live.py --mock
```

مرورگر باز می‌شود (`http://127.0.0.1:8765`). پنج ردیف با واترمارک MOCK روی سؤال‌های ساختگی. این تمرین ضبط است: پنجرهٔ مرورگر را ۱۶۰۰×۹۰۰ کن، OBS را روی آن تنظیم کن، کلید **K** کارت‌های کارنامه را باز و بسته می‌کند، `?cards` در نشانی هم آن‌ها را بلافاصله در پایان باز می‌کند. **هیچ تصویر MOCK در نسخهٔ نهایی نمی‌آید.**

## ۵. پیش‌آزمون پولی (۱۰ سؤال برای هر مدل)

```bash
python3 $A/konkur_prep.py validate
python3 $A/konkur_run.py plan --limit 10
HOMODYNE_NO_FALLBACK=1 python3 $A/konkur_run.py run --limit 10
python3 $A/konkur_run.py report
```

`run` اول سقف دلار را نشان می‌دهد و `[y/N]` می‌پرسد. سقف «UPPER BOUND / fallback» عمداً بالاست (قیمت ساختگی بالا × سقف کامل خروجی)؛ قیمت واقعی بعد از پرکردن `prices.json` می‌آید. بعد `artifact/results/<run>/report.md` را با Claude بخوان:

- [ ] هر پنج مدل جواب `{"choice": …}` دادند (ستون `unparsed` صفر یا نزدیک صفر). اگر یک مدل schema را رد کرد ← فقط برای همان slot در `models.json` بنویس `"no_schema": true` و پیش‌آزمون را تکرار کن. نام پوشهٔ اجرا خودبه‌خود عوض می‌شود، پس جواب‌های با schema و بی schema قاطی نمی‌شوند (cache هم مال همان پوشه است، پس پیش‌آزمون ۱۰ سؤالی برای هر پنج مدل دوباره پرسیده و دوباره پرداخت می‌شود؛ هزینه‌اش کم است).
- [ ] سؤال شکل‌دار به هر پنج مدل رسید (ستون تصویر؛ خطای API نیست).
- [ ] برای دو مدل باز، ستون served در report بعد از «via» فقط یک میزبان OpenRouter نشان داد؟ اگر چند میزبان بود، یا مدل دیگری انتخاب کن یا در قاب ۴ بگو.
- [ ] `refused/fallback/truncated` صفر یا توضیح‌داده‌شده.
- [ ] دلار هر سؤال × تعداد کل سؤال‌ها = بودجهٔ اجرای کامل؛ سقف حساب‌ها را بر همین اساس بگذار.
- [ ] `reasoning` برای OpenAI و OpenRouter گزارش شد؟ (اگر نه، گزارش «گزارش نشده» می‌نویسد؛ ایرادی ندارد ولی در قاب ۱۱ بگو.)

جواب‌های پیش‌آزمون در cache می‌مانند؛ اجرای کامل دوباره برایشان پول نمی‌دهد.

## ۶. اجرای کامل

```bash
caffeinate -dims &                                   # مک نخوابد
HOMODYNE_NO_FALLBACK=1 python3 $A/konkur_live.py --live
```

- همان plan و `[y/N]`، بعد تابلو باز می‌شود و پنج مدل هم‌زمان شروع می‌کنند. اگر می‌خواهی کل اجرا را ضبط کنی، OBS را قبل از y روشن کن؛ ولی لازم نیست: بازپخش همان زمان‌بندی را دارد.
- مدت: چند صد سؤال × پنج مدل؛ مدل‌های فکرکننده ممکن است چند ساعت طول بکشند (هنوز اندازه‌گیری نشده؛ پیش‌آزمون سرنخ می‌دهد).
- **اگر قطع شد** (اینترنت، خواب، Ctrl-C): همان دستور را دوباره بزن. جوابی که بیش از ۹۰۰ ثانیه طول بکشد خطا ثبت می‌شود (`HOMODYNE_HTTP_TIMEOUT`) و در اجرای بعدی دوباره پرسیده می‌شود. سؤال‌های جواب‌داده دوباره پرسیده نمی‌شوند. زمان اولین اندازه‌گیری نگه داشته می‌شود.
- خطای API (مثلاً سهمیه) سؤال را «بی‌جواب» نمی‌کند؛ فقط در اجرای بعدی دوباره پرسیده می‌شود. پیش از `report` مطمئن شو پیام «all questions answered» آمده.

```bash
python3 $A/konkur_run.py report
```

`results/<run>/report.md` (جدول‌ها)، `summary.json` و `spoken-fa.txt` (جمله‌های قاب ۸ تا ۱۰). به Claude بگو «report آماده است»؛ جای خالی‌های متن، دک و بستهٔ انتشار را با همین عددها پر می‌کند، شاخه‌های نامربوط را برمی‌دارد و `NOT RUN YET` را پاک می‌کند.

## ۷. بازپخش برای ضبط

```bash
python3 $A/konkur_live.py --replay <run> --speed 20     # «بازپخش · ×۲۰» روی صفحه
python3 $A/konkur_live.py --replay <run>                # زمان واقعی
```

`<run>` نام پوشه در `private/konkur/runs/` است (`report` آن را چاپ می‌کند). برای اجرایی که چند بار ازسرگرفته شده، `--session N` فایل `events-N.jsonl` را انتخاب می‌کند (پیش‌فرض: طولانی‌ترین).
